🔴 SQL Injection - Login Bypass

EASY

Vulnerability Type

SQL Injection (A03:2021)

Attack Difficulty

Very Easy - No tools required, just modify form input

Step-by-Step Attack

1. Open login.html
2. Enter Email: ' OR '1'='1
3. Enter Password: anything
4. Click Login button

What Happens

The PHP code constructs this query:

SELECT * FROM users WHERE email = '' OR '1'='1' AND password = 'anything'

Since '1'='1' is always TRUE, the query returns all users, bypassing authentication!

Vulnerable Code Location

backend/login.php - lines containing direct concatenation

⚠️ Impact: Attacker gains access to admin account and can access all system functions

Other Payloads to Try

admin' -- ' OR 1=1 -- ' UNION SELECT 1,2,3 -- ' OR '1'='1' /*

🔴 SQL Injection - Search Function

EASY

Vulnerability Type

SQL Injection in Search (A03:2021)

Attack Difficulty

Very Easy - Same technique as login, different endpoint

Step-by-Step Attack

1. Open jobs.html
2. Click on search box
3. Type: %' OR '1'='1
4. Click Search button

What Happens

The vulnerable query becomes:

SELECT * FROM jobs WHERE title LIKE '%' OR '1'='1%'

Returns ALL jobs from database (not just matching search)

Data Exposed

  • Private job listings
  • Draft jobs not ready for publication
  • Jobs from all companies
  • Potentially archived/deleted jobs
⚠️ Impact: Information disclosure - attacker sees data they shouldn't have access to

🔴 Broken Access Control - Admin Panel

EXTREMELY EASY

Vulnerability Type

Broken Access Control (A01:2021)

Attack Difficulty

Trivial - No authentication required at all

Step-by-Step Attack

1. Open admin.html in browser
2. That's it! Full admin access granted

Access Gained

  • ✅ View all user accounts

  • ✅ Access database credentials
  • ✅ See API keys
  • ✅ View JWT secrets
  • ✅ Access sensitive config

⚠️ CRITICAL Impact: Complete system compromise, all credentials leaked, database access gained

🔴 IDOR - Edit Other Users' Jobs

VERY EASY

Vulnerability Type

IDOR - Insecure Direct Object References (A01:2021)

Attack Difficulty

Very Easy - Just modify URL parameter

Step-by-Step Attack

1. Open jobs.html
2. Click "Edit Job" button on job_id=1
3. URL becomes: job-edit.html?job_id=1
4. Change URL to: job-edit.html?job_id=2
5. Now editing a different company's job!

What Attacker Can Do

  • ❌ Edit competitor's job listings
  • ❌ Delete job postings
  • ❌ Change salary information
  • ❌ Modify job requirements
  • ❌ Deface listings
  • ❌ Reroute applications

How to Enumerate

Since IDs are sequential and predictable:

job-edit.html?job_id=1 job-edit.html?job_id=2 job-edit.html?job_id=3 job-edit.html?job_id=4 ... (try all IDs 1-1000)
⚠️ Impact: Business disruption, data corruption, competitive sabotage

🔴 Brute Force - No Rate Limiting

MEDIUM

Vulnerability Type

Identification & Authentication Failures (A07:2021)

Attack Difficulty

Medium - Requires scripting but no technical barriers

Step-by-Step Attack

1. Write a script to POST login requests
2. Try password combinations:
  • password
  • password123
  • admin
  • admin123
  • 12345678
3. No rate limiting = unlimited attempts
4. Eventually find working password

Why This Works

No protection mechanisms:

  • ❌ No rate limiting (can try 1000s of passwords/min)
  • ❌ No account lockout (after N failed attempts)
  • ❌ No CAPTCHA (stops automated attacks)
  • ❌ No 2FA/MFA (additional factor)

Example Attack Code (Conceptual)

passwords = ['admin', 'admin123', '12345678', ...] for password in passwords: response = POST(login.php, email, password) if response.contains('Welcome'): print(f"Found password: {password}") break
⚠️ Impact: Account takeover, unauthorized access, privilege escalation

🔴 Security Misconfiguration - Credential Theft

EXTREMELY EASY

Vulnerability Type

Security Misconfiguration (A05:2021)

Attack Difficulty

Trivial - View page source

Step-by-Step Attack

1. Open admin.html
2. Right-click → View Page Source
3. Search for "Database" or "password"
4. Find all credentials listed!

Credentials Exposed

Database Host: 192.168.199.250 Database User: root Database Password: password123 Database Name: joblink_demo JWT Secret: super_secret_key_12345_exposed_in_source API Key: api_key_12345_exposed API URL: http://192.168.199.250:8000/backend/

What Attacker Can Now Do

  • 🔓 Connect directly to MySQL database
  • 🔓 Create malicious JWTs for account impersonation
  • 🔓 Make API calls as system
  • 🔓 Extract all data
  • 🔓 Modify database records

Additional Exposure

In browser Developer Tools (F12):

// Console shows: const API_KEY = 'api_key_12345_exposed'; const API_URL = 'http://192.168.199.250:8000/backend/'; console.log('Admin panel loaded - using API:', API_URL);
⚠️ CRITICAL Impact: Direct database access, API key compromise, complete system takeover

🔴 Using Exposed API Keys

MEDIUM

Vulnerability Type

Security Misconfiguration + Broken Access Control

Attack Difficulty

Medium - Requires HTTP client but straightforward

Step-by-Step Attack

1. Obtain API key from admin.html source
2. Open tool like Postman or use curl
3. Make requests with exposed credentials
4. Access backend APIs without authentication

Attack Examples

# Using exposed API key curl -H "X-API-Key: api_key_12345_exposed" \ http://192.168.199.250:8000/backend/get-users.php # Using exposed JWT secret to create fake tokens jwt = encode(payload, secret=super_secret_key_12345) headers = {"Authorization": f"Bearer {jwt}"} response = requests.get(url, headers=headers)

What Attacker Can Access

  • 🔓 /backend/get-users.php - All user data
  • 🔓 /backend/get-jobs.php - All jobs
  • 🔓 /backend/update-user.php - Modify users
  • 🔓 /backend/delete-job.php - Delete jobs
  • 🔓 /backend/admin-only.php - Admin functions

Why This Fails

No authentication check because:

  • ❌ API key is hardcoded in frontend
  • ❌ Same key used for all operations
  • ❌ Key has unlimited permissions
  • ❌ No expiration on key
  • ❌ Key exposed in source code
⚠️ CRITICAL Impact: Unauthorized API access, data theft, system compromise

🔒 How These Would Be Fixed

SQL Injection Fix

// BEFORE (Vulnerable) $query = "SELECT * FROM users WHERE email = '" . $email . "'"; // AFTER (Secure) $stmt = $conn->prepare("SELECT * FROM users WHERE email = ?"); $stmt->bind_param("s", $email); $stmt->execute();

Access Control Fix

// BEFORE (Vulnerable) // Anyone can access admin.html // AFTER (Secure) session_start(); if (!isset($_SESSION['user_id']) || $_SESSION['role'] !== 'admin') { header('Location: login.html'); exit; }

Secrets Management Fix

// BEFORE (Vulnerable) const API_KEY = 'api_key_12345_exposed'; // In frontend! // AFTER (Secure) // Store in backend .env $api_key = $_ENV['API_KEY']; // NEVER expose in frontend code // Use backend API endpoint instead
